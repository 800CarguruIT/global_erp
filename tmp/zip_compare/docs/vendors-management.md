# Vendors Management

## Vendor Setup, Classification & Access Control Guide

---

## Who Should Read This?

* Company Administrators
* Procurement Managers
* Operations Managers responsible for vendor onboarding
* Security or IT Administrators supporting vendor access

---

# 1. What Is Vendors Management?

Vendors Management is the area where company-level administrators manage supplier and partner records used in procurement and service workflows.

Each vendor record represents a business partner that can provide parts, services, or operational support.

Vendor setup affects:

* Procurement cycle accuracy
* Purchase order routing
* Cost control and comparison
* Delivery tracking
* Audit and compliance visibility

---

# 2. What Can You Do on This Page?

Through Vendors Management, you can:

* View all vendors under your company
* Create new vendor records
* Edit vendor details
* Activate or deactivate vendors
* Maintain procurement-ready vendor data

This ensures only valid and approved vendors are used in operations.

---

# 3. Why Vendors Management Is Important

Strong vendor control helps your company:

* Keep supplier data clean and reliable
* Reduce purchasing errors
* Improve procurement speed
* Protect financial accuracy
* Maintain accountability and traceability

Without proper vendor operations control, procurement and reporting quality will degrade.

# 4. A. Viewing and Searching Vendors

## What Information Is Typically Visible

* Vendor name
* Vendor code
* Contact details
* Service category (if configured)
* Payment or tax details (if configured)
* Status (Active / Inactive)

---

## Why This Matters

This allows administrators to:

* Confirm which vendors are currently approved
* Review partner data quality
* Verify vendor readiness before issuing POs
* Support compliance and audit checks

---

# 5. B. Creating a New Vendor

## When to Create a Vendor

Create a vendor when:

* A new supplier is approved
* A new workshop partner is onboarded
* A new service provider is required for operations

---

## Required Information

When creating a vendor, define:

* Vendor name
* Vendor code (must be unique within company)
* Contact person and communication details
* Vendor category or service scope
* Address and location details
* Status (normally Active)

---

## Example Setup Flow

1. Open Vendors Management
2. Click Add Vendor
3. Enter vendor details
4. Set category and contact information
5. Set status to Active
6. Save

---

## Post-Creation Validation

After creation, confirm:

✔ Vendor appears in the list  
✔ Vendor code is unique  
✔ Contact details are correct  
✔ Vendor is selectable in procurement workflows  
✔ Access and mapping rules are correct

---

# 6. C. Editing an Existing Vendor

## When Should You Edit a Vendor?

* Contact person changes
* Address or profile details change
* Service scope is updated
* Data correction is required

---

## What Can Be Updated?

* Vendor display name
* Contact details
* Address details
* Category or service information
* Configuration fields used by procurement

After editing, verify changes are reflected in vendor list and procurement modules.

---

# 7. D. Managing Vendor Status (Active / Inactive)

## When to Deactivate a Vendor

* Contract ends
* Vendor performance is non-compliant
* Temporary suspension is required
* Vendor is no longer used

---

## Why Deactivate Instead of Delete?

Never delete operational vendors when transactions exist.

Deactivation:

* Preserves procurement history
* Maintains financial traceability
* Keeps audit logs intact
* Prevents new transactions

Deleting vendors may break purchase history and reporting references.

---

## Reactivating a Vendor

If the vendor is approved again:

* Change status to Active
* Validate procurement module visibility
* Reconfirm commercial and compliance details

---

# 8. E. Operational Validation Checklist

After creating, editing, or changing status, confirm:

✔ Vendor appears correctly in list  
✔ Vendor code and profile data are correct  
✔ Vendor is available only where required  
✔ Procurement workflows use correct vendor mapping  
✔ Inactive vendors cannot receive new transactions

---

# 9. Security & Operations Control Principles

For controlled vendor administration:

* Restrict vendor create/edit permissions to authorized roles
* Review active vendor list periodically
* Deactivate unused vendors promptly
* Record reasons for major vendor changes
* Ensure procurement approvals remain role-based
