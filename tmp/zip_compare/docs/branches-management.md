---

## Who Should Read This?

# 1. What Is Branches Management?

Branches Management is the area where company-level administrators define and control all operational locations inside the **Global ERP system**.

Each branch represents a real operational unit under a company, such as:

* Workshop
* Service center
* Recovery unit
* Roadside assistance hub
* Regional operations site

The branch structure directly affects:

* Job routing
* User access control
* Inventory tracking
* Financial reporting
* Performance analysis

---

# 2. What Can You Do on This Page?

Through Branches Management, you can:

* View all branches under your company
* Create new operational branches
* Edit branch information
* Activate or deactivate branches
* Define ownership structure
* Define operational service type

This ensures that each operational location is properly structured and controlled.

# 3. Branch Classification (Critical Setup Rule)

Every branch must be classified using **two dimensions**:

## A. Ownership Type

## B. Branch Operational Type

This classification drives workflows, reporting logic, and operational controls.

---

## A. Ownership Type

### 🏢 Own

The branch is fully owned and operated by your company.

Typical characteristics:

* Internal staff
* Internal financial control
* Direct management oversight
* Company-controlled inventory

---

### 🤝 3rd Party

The branch is operated by an external partner but managed inside the ERP system.

Typical characteristics:

* Partner-managed operations
* Controlled through ERP workflows
* Performance tracked via system reports
* May have contractual service agreements

---

## B. Branch Operational Type

### 🚗 RSA (Roadside Assistance)

Handles on-site emergency support and breakdown assistance.

### 🚛 Recovery

Handles towing and vehicle transport operations.

### 🔧 Workshop

Handles inspections, repairs, and technical execution of jobs.

---

## Why Correct Classification Matters

Incorrect classification may cause:

* Incorrect job routing
* Reporting inaccuracies
* Wrong performance analytics
* Operational confusion
* Misaligned financial tracking

Always verify classification during setup.

# 6. B. Creating a New Branch

## When to Create a Branch

Create a branch when:

* A new operational location opens
* A new workshop is launched
* A partner branch is onboarded
* You need operational separation for reporting or control

---

## Required Information

When setting up a branch, define:

* Branch name
* Branch code (must be unique within the company)
* Ownership type (Own or 3rd Party)
* Branch type (RSA, Recovery, Workshop)
* Country and city
* Address details
* Primary contact
* Status (normally Active)

---

## Example Setup Flow

1. Open Branches Management
2. Click Add Branch
3. Enter branch details
4. Select ownership and operational type
5. Set status to Active
6. Save

---

## Post-Creation Validation

After creation, confirm:

✔ Branch appears in the list
✔ Branch code is unique
✔ Classification is correct
✔ Branch appears in operational modules
✔ Users can be assigned to the branch

# 8. D. Managing Branch Status (Active / Inactive)

## When to Deactivate a Branch

* Branch temporarily suspended
* Operations merged into another location
* Partner contract ended
* Site permanently closed

---

## Why Deactivate Instead of Delete?

Never delete operational branches.

Deactivation:

* Preserves job history
* Maintains inventory traceability
* Protects financial reports
* Keeps audit trail intact
* Prevents new transactions

Deleting a branch may break reporting, accounting, and job references.

---

## Reactivating a Branch

If operations resume:

* Change status to Active
* Confirm workflows operate correctly
* Revalidate user assignments

---

# 9. E. Operational Validation Checklist

After creating, editing, or changing status, confirm:

✔ Branch appears correctly in list
✔ Branch code and location are accurate
✔ Ownership and operational type are correct
✔ Users are properly mapped
✔ Reports reflect branch correctly
✔ Inactive branches cannot initiate new transactions

# 10. Security & Operational Control Principles

For strong branch administration:

* Restrict branch creation to authorized admins
* Review branch structure periodically
* Deactivate unused branches promptly
* Record reasons for major classification or status changes
* Ensure role-based access aligns with branch structure
