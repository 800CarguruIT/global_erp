# Recovery Request (Web View)

## Company Operations Guide

### Who Should Read This?

- Company Administrators
- Branch Operations Managers
- Dispatch Coordinators
- Workshop and Recovery Supervisors

## 1. What Is Recovery Request?

Recovery Request is the company workflow used when a vehicle cannot continue operation and must be transported by recovery unit.

This process connects:

- Customer and vehicle context
- Lead and job workflow
- Dispatch and field execution
- Branch handover and closure

## 2. Where to Access in Web View

Recovery requests are managed from company operations pages:

- Company dashboard
- Leads and service request context
- Recovery queue / operations board

The request must stay linked to the same customer and car record.

## 3. Creating a Recovery Request

### Step-by-step

1. Open the customer or lead context in company module.
2. Click `Create Recovery Request`.
3. Select the vehicle.
4. Enter issue details and pickup location.
5. Set destination branch/workshop.
6. Set priority and preferred schedule.
7. Save the request.

After save:

- Recovery reference number is generated.
- Request appears in operations queue.
- Assigned teams can start dispatch actions.

## 4. Main Fields in Web Form

- Request Number (auto-generated)
- Customer
- Vehicle
- Pickup Location
- Destination Branch
- Priority
- Requested Time
- Notes / Failure Description
- Status

## 5. Status Flow (Web)

- New
- Assigned
- En Route
- Vehicle Loaded
- Delivered to Branch
- Closed
- Cancelled

Use status updates in real time for accurate operations tracking.

## 6. Assignment and Dispatch

After creation:

1. Open request in operations queue.
2. Assign driver/recovery unit.
3. Confirm dispatch.
4. Track progress by status until delivery.

## 7. Validation and Closure

Before closing:

- Verify vehicle received at destination.
- Verify destination branch handover.
- Confirm timestamps and notes are complete.
- Confirm no pending exception.

Then mark request as `Closed`.

## 8. Operational Controls

- Only authorized roles can create/assign/cancel.
- Status changes should be auditable.
- Cancel action should require reason.
- Inactive branches should not receive new requests.

## Summary

Recovery Request (Web View) gives company teams a controlled transport workflow from request intake through dispatch and branch delivery, with full traceability.
